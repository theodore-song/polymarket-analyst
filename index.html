How real money should work

  1. User owns funds — connect a wallet or regulated brokerage account; the site should not custody deposits directly.
  2. Consent per agent — users choose which agents can trade and the maximum amount each may control.
  3. Execution layer — agent signals become signed user orders through Polymarket's trading flow or a compliant partner.
  4. Risk controls — stop-loss, gain-stop, exposure caps, market exclusions, and emergency pause stay visible before any order is sent.

Compliance checklist

  • Eligibility, location, age, KYC, and sanctions screening before real trading.
  • Clear disclosure that prediction markets are risky and users can lose the full amount committed.
  • No pooled customer funds unless handled by a properly regulated structure.
  • Audit logs for every signal, user approval, order, fill, stop, and withdrawal.

ℹ️ The competition

Every agent starts with $10,000 in paper money. Five core strategies use disciplined entry rules, while five aggressive strategies pursue catalysts, durable trends, breakouts, asymmetric tails, and concentrated conviction. Aggressive agents may size confirmed setups more heavily, but cash is retained whenever their strategy has no qualifying signal.

The live cycle

  1. Fetch — load the 500 most active eligible Yes/No Polymarket markets and tag each by category.
  2. Score — rank those active markets 0–100 by conviction and estimate edge vs. a fair-value model.
  3. Suggest — surface the strongest picks per category with a plain-English rationale.
  4. Compete — the strategy agents trade the same suggestions their own way, stop-loss weak positions, scale out through gain-stop tiers, exit stale or fading trades, then snapshot equity.

Device sync

Portfolios, returns, reports, suggestions, and chart history now sync through the site automatically. Copy Sync and Import Sync remain as a fallback for moving the exact state between devices.

Real-money trading requirements

before enabling deposits
  1. Eligibility — identity checks, location restrictions, age checks, terms acceptance, and sanctions screening.
  2. Wallets — non-custodial wallet connection or Polymarket deposit-wallet flow so users sign orders themselves.
  3. Accounts — production login, sign-out, password reset, consent records, portfolio history, and secure sessions.
  4. Funds — compliant deposit/withdraw rails, webhooks, reconciled balances, statements, tax/accounting exports, and customer support.
  5. Execution — order router using Polymarket CLOB authentication, signed orders, cancellations, fill tracking, idempotency, retries, and stale-order protection.
  6. Risk controls — server-side user permissions for each agent, exposure limits, stop rules, emergency pause, market blacklists, and withdrawal access at all times.
  7. Operations — monitoring, alerts, security review, audit retention, incident response, and rollback plan.
